# BSB Download Formats

What each file on the Berean Standard Bible download page contains, inspected 2026-10-27, and what each means for the data builder's text importer. The download page itself carries no descriptions; everything below comes from the files. Input to the open Design item "translation text input format(s) the builder accepts".

## Summary

| File | What it is | Keeps couplet lines | Headings, footnotes, cross refs | Parse effort in Swift |
|---|---|---|---|---|
| `bsb.txt` | One tab-separated row per verse | No | No | Trivial |
| `bsb_usfm.zip` | Backslash-marker text, one file per book | Yes | Yes | Hand-written tokenizer |
| `bsb_usx.zip` | Same tree as XML | Yes | Yes | XMLParser, verse-state tracking |
| `bsb_usj.zip` | Same tree as JSON (USFM 3.1) | Yes | Yes | Codable recursive enum, verse-state tracking |
| `bsb.epub` | XHTML chapters for e-readers | Presentational only | Presentational only | Not worth it |
| `bsb-vbv.docx` | One verse per Word paragraph | No | No | OOXML walk for what bsb.txt already gives |
| `bsb_tables.tsv` / `.xlsx` | One row per original-language word, whole Bible | Via HTML paragraph classes | Yes | Column reassembly; not a display-text source |

USFM is the only one of these formats eBible.org also serves for KJV, WEB, and ASV (checked 2026-10-27: `eng-web_usfm.zip`, `eng-kjv2006_usfm.zip`, `eng-asv_usfm.zip`, and `engbsb_usfm.zip` return 200; the `_usx.zip` and `_usj.zip` names return 404). A USFM importer covers all four free texts; USX or USJ would be BSB-only.

## Details

### Text (`bsb.txt`, 4.3 MB)

Two header lines (attribution, public-domain dedication), then `Verse<tab>Berean Standard Bible` and one row per verse: `Proverbs 26:4<tab>Do not answer a fool according to his folly, or you yourself will be like him.` UTF-8 with BOM, CRLF line endings.

- Pros: a five-line importer; verse identity explicit on every row.
- Cons: no poetry line breaks, no section headings, no footnotes, no cross references. Proverbs is almost entirely couplets, so the line structure is lost at import and cannot be recovered.

### USFM (`bsb_usfm.zip`, `PRO.usfm` 98 KB, 67 files)

Plain text with backslash markers. Marker inventory for Proverbs: `\q1` 909 and `\q2` 939 (the two lines of each couplet), `\v` 915, `\b` 518, `\s1` 39 and `\s2` 30 (headings), `\r` 7 (parallel-passage refs), `\li1` 27 (list lines), `\p` 11, `\f` 87 footnotes with `\fr`, `\ft`, `\fqa` inside, `\ref` 19. Footnotes sit inline in the middle of verse text:

```
\q1 \v 3 Never let loving devotion\f + \fr 3:3 \ft Forms of the Hebrew \fqa chesed \ft are translated here ...\f* or faithfulness leave you;
\q2 bind them around your neck,
```

- Pros: keeps every structural element. The one format all four free texts ship in, so one importer covers BSB, KJV, WEB, and ASV.
- Cons: hand-written tokenizer, since Swift has no mature USFM library. The second line of a couplet is a `\q2` line with no verse number, so the importer carries verse state across lines. Footnotes must be stripped or lifted out of the verse text.

### USX (`bsb_usx.zip`, `PRO.usx` 184 KB)

The same tree as XML. The verse is a milestone element inside paragraphs, not a container:

```xml
<para style="q1"> <verse style="v" number="4" />Do not answer a fool according to his folly,</para>
<para style="q2">or you yourself will be like him.</para>
```

- Pros: Foundation's XMLParser reads it with no dependency. Same structure as USFM, no loss.
- Cons: verses span `para` elements, so the importer still reassembles verse text across elements and tracks the current verse as state. Not served by eBible.org for KJV, WEB, or ASV, so it would be a BSB-only importer.

### USJ (`bsb_usj.zip`, `PRO.usj` 460 KB)

The same tree as JSON, schema version 3.1, generated by a converter (the book node reads "Autogenerated BSB by bsb2usfm"). Nodes are typed objects with a `content` array mixing strings and child nodes:

```json
{"type":"para","marker":"q1","content":[" ",{"type":"verse","marker":"v","number":"4"},"Do not answer a fool according to his folly,"]}
```

- Pros: Codable with a small recursive enum and nothing else; the easiest of the three to parse and to write tests against.
- Cons: same milestone model as USX. Newest of the three with the fewest tools. Not served by eBible.org for KJV, WEB, or ASV, so choosing it leaves the builder needing a USFM importer anyway.

### eBible (`bsb.epub`)

Zipped XHTML chapters for e-readers.

- Pros: none for the builder.
- Cons: verse markup is presentational, the structure is whatever the epub generator emitted, and extraction means parsing XHTML with no schema.

### Verse by Verse (`bsb-vbv.docx`)

The same text laid out one verse per paragraph in Word; the source for the VBV PDFs.

- Pros: none over the Text file.
- Cons: unzipping OOXML and walking paragraph runs to get what `bsb.txt` gives directly.

### Translation Tables (`bsb_tables.tsv` 85 MB, 754,648 rows; `.xlsx` is the same data)

One row per original-language word in BSB word order, whole Bible. Columns, in order: Heb Sort, Greek Sort, BSB Sort, Verse, Language, WLC/Nestle word (two columns, the second with textual-variant marking), Translit, Parsing (two columns with the same header), Str Heb, Str Grk, VerseId, Hdg, Crossref, Par, Space, begQ, BSB version, pnc, endQ, footnotes, End text.

Proverbs 26:4 as rows (BSB Sort, Hebrew, transliteration, parsing, Strong's, English):

| 392048 | אַל־ | ’al- | Adv | 408 | Do not |
|---|---|---|---|---|---|
| 392049 | תַּ֣עַן | ta·‘an | V-Qal-Imperf.Jus-2ms | 6030 | answer |
| 392050 | כְּ֭סִיל | kə·sîl | N-ms | 3684 | a fool |
| 392051 | כְּאִוַּלְתּ֑וֹ | kə·’iw·wal·tōw | Prep-k, N-fsc, 3ms | 200 | according to his folly |
| 392052 | פֶּֽן־ | pen- | Conj | 6435 | or |
| 392053 | אָֽתָּה׃ | ’āt·tāh | Pro-2ms | 859 | you yourself |
| 392054 | תִּשְׁוֶה־ | tiš·weh- | V-Qal-Imperf-2ms | 7737 | will be like him |
| 392055 | לּ֥וֹ | lōw | Prep, 3ms | | . . . |

Proverbs counts: 915 rows carry a VerseId (first word of each verse only), 66 headings, 8 cross references, 87 footnotes. Paragraph structure arrives as HTML fragments in the Par column (`<p class=|indent1|>`, `<p class=|hdg|>`).

- Pros: word-level alignment between Hebrew and English with Strong's numbers and morphology. Direct source for the Hebrew-words cloud raised in the discuss session and for a keyword layer that survives a translation change, since Strong's numbers are version-independent.
- Cons: not a display-text source. English must be reassembled from fragments using the Space and pnc columns; some rows render as ". . ." because their meaning merged into a neighbor's phrase; layout is HTML fragments; verse identity must be carried forward from the first word of each verse; two columns share the name Parsing. The largest file by far.
