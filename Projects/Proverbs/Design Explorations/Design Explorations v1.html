Four ways through Proverbs

Three visual directions for the cloud, the passage and the trail, plus four patterns for composing a scenario from several tags. Every row walks the same session — conflict with a neighbor → 15:1 → anger → 29:11, with a fork between 16:32 and 14:29 — so the directions compare like for like. Nothing on any screen is written by the app: the words are the text (Berean Standard Bible), the tags, and the controls.

Direction D

Composing a scenario

The primary use case: a scenario is several tags across axes. Four ways to build the query, with full matches ranked above partial ones and related tags suggested. Same scenario on every screen: conflict with a neighbor + anger + neighbor.

What the screens raise but cannot settle

Hiding versus dimming

In D2, tags that share no passages with the chosen set go dim. Hiding them would be cleaner but breaks the rule that every curated tag stays in the cloud (ISC-10).

Order within a band

Full matches rank above partial ones (ISC-44). Within a band, rows could sort by how many chosen tags they carry, by link weight, or by book order. The screens assume weight.

Saving a scenario

“Save as context group” on the results screen quietly turns a query into the seed of a context group. Whether that is the intended front door to groups is an open decision.

Tree as surface or panel

A and C treat the trail as a screen of its own; B pulls it up over the cloud. The choice decides how often the user sees the fork they could return to.

Cloud density

A scrolls, B maps, C ranks. Each handles “every tag must be present” differently; only a full-count prototype will show which survives the real vocabulary.
